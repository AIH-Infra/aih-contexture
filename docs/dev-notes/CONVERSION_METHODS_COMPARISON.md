|------|---------|---------|--------|------|------|

| **Surya Layout + OCR** | 内置深度学习模型 | ⭐⭐⭐ 中等 | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐ 快 | ⭐⭐⭐⭐⭐ 免费 |
| **YOLO + Surya** | YOLO 检测 + Surya OCR | ⭐ 最复杂 | ⭐⭐⭐⭐ 高 | ⭐⭐⭐⭐⭐ 最快 | ⭐⭐⭐⭐⭐ 免费 |

## 详细对比

### 1. VLM Direct（新方案）

#### 工作流程
```
PDF → 提取页面图像 → VLM 处理 → Markdown
```

#### 优势
- ✅ **实现最简单**：只需 2 个文件，450 行代码
- ✅ **依赖最少**：只需 openai + pillow
- ✅ **配置最简单**：只需 API key
- ✅ **效果最好**：利用 GPT-4o/Claude 的理解能力
- ✅ **立即可用**：无需训练、无需 Docker
- ✅ **支持复杂文档**：手写、古籍、多语言

#### 劣势
- ⚠️ **速度慢**：每页 1-5 秒
- ⚠️ **成本高**：100 页约 $0.20-$3.00
- ⚠️ **需要网络**：依赖外部 API

#### 适用场景
- 快速原型开发
- 复杂文档处理
- 高质量要求
- 小批量处理（<100 页）

#### 性能数据
- **速度**：2-5 秒/页
- **成本**：$0.002-$0.03/页
- **准确度**：95-98%
- **GPU 要求**：无

#### 使用示例
```bash
python vlm_direct_convert.py input.pdf --api-key sk-xxx
```

### 2. Surya Layout + OCR（默认方案）

#### 工作流程
```
PDF → Surya Layout → Surya OCR → 结构化 → Markdown
```

#### 优势
- ✅ **内置**：无需额外配置
- ✅ **稳定**：经过充分测试
- ✅ **免费**：无运行成本
- ✅ **支持多语言**：90+ 语言
- ✅ **可离线运行**：无需网络

#### 劣势
- ⚠️ **准确度中等**：85-90%
- ⚠️ **速度中等**：1-2 秒/页（GPU）
- ⚠️ **复杂文档效果差**：手写、古籍

#### 适用场景
- 通用文档处理
- 快速测试
- 没有 GPU 的环境
- 不需要最高准确度

#### 性能数据
- **速度**：1-2 秒/页（GPU），5-10 秒/页（CPU）
- **成本**：$0（免费）
- **准确度**：85-90%
- **GPU 要求**：可选（推荐 6GB+）

#### 使用示例
```bash
python convert_single.py input.pdf output_dir
```

---

### 3. DocLayout-YOLO + Surya（生产方案）

#### 工作流程
```
PDF → YOLO Layout → Surya OCR → 结构化 → Markdown
```

#### 优势
- ✅ **速度最快**：50-100ms/页（layout）
- ✅ **准确度高**：95%+
- ✅ **免费**：无运行成本
- ✅ **资源占用少**：2-3GB 显存
- ✅ **可离线运行**：无需网络

#### 劣势
- ⚠️ **部署复杂**：需要 Docker + NVIDIA Runtime
- ⚠️ **需要 GPU**：推荐 6GB+ 显存
- ⚠️ **初次设置耗时**：1-2 小时

#### 适用场景
- 生产环境
- 批量处理
- 需要高速度和高准确度
- 有 GPU 资源

#### 性能数据
- **速度**：0.5-1 秒/页（GPU）
- **成本**：$0（免费）
- **准确度**：95%+
- **GPU 要求**：必需（推荐 6GB+）

#### 使用示例
```bash
# 1. 部署 Docker 服务
docker run -d --gpus all -p 11900:11900 doclayout-yolo

# 2. 配置 Marker
python convert_single.py input.pdf output_dir \
    --layout_backend yolo \
    --yolo_base_url http://localhost:11900
```

### 4. VLM Layout + VLM OCR（高质量方案）

#### 工作流程
```
PDF → VLM Layout → VLM OCR → 结构化 → Markdown
```

#### 优势
- ✅ **准确度高**：95%+
- ✅ **理解复杂布局**：手写、古籍、特殊排版
- ✅ **支持自定义提示词**：针对特定文档优化
- ✅ **无需 GPU**：使用云端 API

#### 劣势
- ⚠️ **速度最慢**：5-10 秒/页
- ⚠️ **成本最高**：100 页约 $5-$10
- ⚠️ **需要网络**：依赖外部 API
- ⚠️ **配置复杂**：需要配置两个 VLM 服务

#### 适用场景
- 复杂文档（古籍、手稿）
- 需要高度定制化
- 小批量处理
- 对成本不敏感

#### 性能数据
- **速度**：5-10 秒/页
- **成本**：$0.05-$0.10/页
- **准确度**：95-98%
- **GPU 要求**：无

#### 使用示例
```bash
python convert_single.py input.pdf output_dir \
    --layout_backend vlm \
    --ocr_backend vlm \
    --openai_api_key sk-xxx
```

## 推荐方案总结

### 场景 1: 快速原型开发
**推荐**: VLM Direct
- 最快落地（5 分钟）
- 效果最好
- 无需复杂配置

### 场景 2: 生产环境批量处理
**推荐**: YOLO + Surya
- 速度最快
- 准确度高
- 完全免费

### 场景 3: 通用文档处理
**推荐**: Surya Layout + OCR
- 内置方案
- 稳定可靠
- 无需配置

### 场景 4: 复杂文档高质量处理
**推荐**: VLM Direct 或 VLM Layout + OCR
- 准确度最高
- 理解能力强
- 支持特殊文档

### 场景 5: 成本敏感
**推荐**: Surya 或 YOLO + Surya
- 完全免费
- 无运行成本
- 可离线运行
