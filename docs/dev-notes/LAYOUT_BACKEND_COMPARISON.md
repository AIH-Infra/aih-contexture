| 后端 | 部署难度 | 速度 | 准确度 | GPU 要求 | 成本 | 推荐场景 |
|------|---------|------|--------|----------|------|----------|
| **Surya** | ⭐ 最简单 | ⭐⭐⭐ 中等 | ⭐⭐⭐ 中等 | 可选 | 免费 | 快速测试、通用文档 |

## 详细分析

### 1. Surya Layout（内置）

**优点**：
- ✅ 无需配置，开箱即用
- ✅ 稳定可靠
- ✅ 支持多种文档类型
- ✅ 可在 CPU 或 GPU 上运行

**缺点**：
- ⚠️ 准确度中等
- ⚠️ 速度中等
- ⚠️ 对复杂布局支持有限

**适用场景**：
- 快速测试和原型开发
- 通用文档处理
- 不需要最高准确度的场景
- 没有 GPU 的环境

**配置**：
```python
config = {
    "layout_backend": "surya"
}
```

---

### 2. DocLayout-YOLO（推荐用于生产）

**优点**：
- ✅ 速度最快（GPU 上可达实时）
- ✅ 准确度最高（专门训练的 YOLO 模型）
- ✅ 资源占用少
- ✅ 免费开源
- ✅ 可离线运行

**缺点**：
- ⚠️ 需要部署 Docker 服务
- ⚠️ 需要 NVIDIA GPU（推荐）
- ⚠️ 初次设置较复杂

**适用场景**：
- 生产环境
- 批量文档处理
- 需要高准确度和高速度
- 有 GPU 资源

**性能数据**：
- 单页处理时间：~50-100ms（GPU）
- 批处理吞吐量：10-20 页/秒
- 显存占用：~2-3GB

**配置**：
```python
config = {
    "layout_backend": "yolo",
    "yolo_base_url": "http://localhost:11900",
    "yolo_confidence_threshold": 0.25
}
```

---

### 3. VLM Layout（视觉语言模型）

#### 3.1 大模型（推荐）

**推荐模型**：
- `gpt-4o` / `gpt-4o-mini`（OpenAI）
- `qwen-vl-max` / `qwen-vl-plus`（通义千问）
- `claude-3-5-sonnet`（Anthropic）

**优点**：
- ✅ 准确度高
- ✅ 理解复杂布局
- ✅ 支持自定义提示词
- ✅ 不需要本地 GPU

**缺点**：
- ⚠️ 速度慢（每页 2-5 秒）
- ⚠️ 需要 API 密钥
- ⚠️ 按调用付费（成本较高）
- ⚠️ 需要网络连接

**适用场景**：
- 复杂文档（古籍、手稿、特殊排版）
- 需要高度定制化
- 小批量处理
- 对成本不敏感

**成本估算**（以 gpt-4o-mini 为例）：
- 单页成本：~$0.001-0.003
- 100 页文档：~$0.10-0.30
- 1000 页文档：~$1-3

**配置**：
```python
config = {
    "layout_backend": "vlm",
    "vlm_layout_base_url": "https://api.openai.com/v1",
    "vlm_layout_model": "gpt-4o-mini",
    "vlm_layout_api_key": "sk-...",
    "vlm_layout_prompt_template": "modern"  # 或自定义
}
```

#### 3.2 小模型（不推荐）

**示例模型**：
- `layout-qwen-3b-best`
- `llava-7b`
- 其他小型 VLM

**问题**：
- ❌ 准确度低（边界框不准确）
- ❌ 标签分类错误率高
- ❌ 阅读顺序混乱
- ❌ 无法处理复杂布局

**为什么会结构混乱**：
1. **模型容量不足**：3B-7B 参数对于视觉理解任务太小
2. **训练数据有限**：小模型通常训练数据较少
3. **泛化能力差**：对训练集外的文档效果差
4. **空间推理弱**：难以准确判断元素位置关系

**结论**：❌ 不推荐用于版面识别

## 推荐方案

### 方案 1: 快速开始（最简单）
```
Surya Layout（内置）
```
- 适合：快速测试、学习使用
- 优点：零配置
- 缺点：准确度和速度中等

### 方案 2: 生产环境（推荐）
```
DocLayout-YOLO（Docker）
```
- 适合：批量处理、生产部署
- 优点：速度快、准确度高、免费
- 缺点：需要部署 Docker 服务

### 方案 3: 复杂文档（高质量）
```
VLM Layout（大模型）
```
- 适合：古籍、手稿、特殊排版
- 优点：准确度最高、可定制
- 缺点：速度慢、有成本

### 方案 4: 混合方案（最优）
```
DocLayout-YOLO（主力） + VLM（特殊情况）
```
- 大部分文档用 YOLO（快速、准确）
- 复杂文档用 VLM（高质量）
- 根据文档类型自动选择

## 常见问题

### Q: 为什么小 VLM 模型效果差？
A: 版面识别需要：
- 精确的空间推理能力
- 大量的文档训练数据
- 复杂的视觉理解能力

3B-7B 参数的模型在这些方面都不足。

### Q: DocLayout-YOLO 必须用 GPU 吗？
A: 不是必须，但强烈推荐：
- **GPU**：50-100ms/页
- **CPU**：500-1000ms/页（慢 10 倍）

### Q: 可以同时使用多个后端吗？
A: 可以！在代码中动态切换：
```python
# 简单文档用 YOLO
if is_simple_document(pdf):
    config["layout_backend"] = "yolo"
# 复杂文档用 VLM
else:
    config["layout_backend"] = "vlm"
```

### Q: 如何评估版面识别质量？
A: 检查以下指标：
1. **边界框准确度**：元素是否被完整框选
2. **标签正确性**：文本、图片、表格是否正确分类
3. **阅读顺序**：元素顺序是否符合阅读习惯
4. **遗漏率**：是否有元素未被检测
